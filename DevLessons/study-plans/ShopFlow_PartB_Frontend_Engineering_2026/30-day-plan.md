# ShopFlow Part B - Frontend Engineering 2026: 30-Day Study Tracker

## How to use this tracker
- Study 2 to 3 hours per day.
- Use 6 days for active study and 1 day for retrospective.
- Keep one notes page for component structure, one for state flow, and one for UX or quality rules.
- End each day with one concrete UI-related output.

## Week 1: Frontend orientation

Day 1:
- Read the headings and section titles.
- Map the document structure in your notes.
- Identify the major frontend themes.

Day 2:
- Read the opening sections carefully.
- Write what the frontend is responsible for.
- Note any assumptions about tools or workflow.

Day 3:
- Capture the main frontend concepts in short definitions.
- Add unfamiliar terms and patterns to a glossary.
- Write a plain-language explanation for each.

Day 4:
- Review any examples or screenshots.
- Explain what each example is showing.
- Note layout, component, or interaction principles.

Day 5:
- Build a glossary grouped by rendering, components, state, styling, or workflow.
- Mark the terms that keep appearing.
- Add one example for each important term.

Day 6:
- Recreate the structure from memory.
- Give a short explanation of the document’s purpose.
- List the sections that need a slower second pass.

Day 7:
- Retrospective day.
- Write what feels clear and what still feels abstract.
- Pick the next section to revisit.

## Week 2: Component structure and state flow

Day 8:
- Revisit your notes.
- Read the component and structure sections.
- Identify the design rules the PDF prefers.

Day 9:
- Focus on component boundaries.
- Write what belongs in a component and what should be delegated.
- Capture advice about separation of concerns.

Day 10:
- Study state flow and data movement.
- Draw a simple diagram of where state comes from and where it goes.
- Note any guidance on local versus shared state.

Day 11:
- Review props, composition, or reusable UI patterns.
- Rewrite the main ideas as short rules.
- Add a small example of how you would apply one rule.

Day 12:
- Compare different component shapes or page layouts.
- Note what makes one pattern cleaner than another.
- Summarize the structure lesson in a paragraph.

Day 13:
- Rebuild a component hierarchy from memory.
- Recite the state flow without looking at notes.
- Identify the weak spots.

Day 14:
- Retrospective day.
- Review all component notes.
- Decide what needs more coding practice.

## Week 3: Usability, accessibility, and quality

Day 15:
- Re-open the quality and user-experience sections.
- Identify the accessibility and responsiveness themes.
- List the terms that connect to user impact.

Day 16:
- Study accessibility guidance carefully.
- Write the practical meaning of each recommendation.
- Turn each into a checklist item.

Day 17:
- Focus on responsiveness and layout adaptation.
- Note how the UI should behave across sizes or contexts.
- Summarize the expectations in your own words.

Day 18:
- Review maintainability or code quality advice.
- Write down patterns that keep frontend code easier to change.
- Mark anti-patterns or warning signs.

Day 19:
- Look for performance or rendering guidance.
- Summarize what helps the UI stay smooth and understandable.
- Add any cautions or tradeoffs.

Day 20:
- Run a closed-book recap of the quality topics.
- Rebuild the usability checklist from memory.
- Write one paragraph explaining why the rules matter.

Day 21:
- Retrospective day.
- Pick the most actionable quality ideas.
- Decide which checklist item should become default.

## Week 4: Review and application

Day 22:
- Review all prior notes.
- Identify the top frontend ideas to keep.
- Mark the sections you still reread often.

Day 23:
- Re-read only the weakest sections.
- Rewrite them with simpler language.
- Remove duplicates and unclear phrasing.

Day 24:
- Create a final frontend principles sheet.
- Include structure, state flow, usability, and maintainability.
- Keep the list short and memorable.

Day 25:
- Sketch one practical UI example using the PDF guidance.
- Explain the component structure and state flow.
- Note how accessibility and quality rules apply.

Day 26:
- Do a full recall test from memory.
- Compare your recall to the source.
- Fix any mismatches in your notes.

Day 27:
- Write the final summary for this PDF.
- Capture the most important frontend lessons.
- Add one concrete practice task for later.

Day 28:
- Run a final closed-book self-test.
- Explain the PDF from memory.
- Mark the remaining weak spots.

Day 29:
- Review the self-test results.
- Fix mistakes in your notes.
- Write the last unresolved question.

Day 30:
- Final retrospective.
- Summarize what you learned overall.
- Decide how you will revisit the material later.
